# v0.2.21

`0.2.21` 是一轮以代码审计为基础的加固版本：修复了在线升级「下载完成却从不安装」的根因，补齐升级包与 FFmpeg 安装包的完整性校验，为投屏中继加上访问控制，并对首页、播放列表与启动路径做了可感知的性能优化。本轮新增 45 项单元测试，全量 213 项通过。

## 在线升级

- 修复升级包下载完成后安装包从未被执行的问题 —— 根因是以 `DETACHED_PROCESS` 启动 PowerShell 时它会立即退出且不执行任何脚本行，现改用 `CREATE_NO_WINDOW`
- 升级包下载后强制三重校验：仅接受 HTTPS 且在 GitHub 发布域名白名单内的地址、比对文件大小、比对 SHA256；任一不通过即删除临时文件并终止升级
- 预期哈希按「GitHub 资产 digest → 同一 Release 的 `SHA256SUMS` 资产 → Release 正文」三级解析，均缺失时在 Windows 下回退 Authenticode 签名校验
- 升级脚本不再落盘，改为 `-EncodedCommand` 内联传入，消除「校验过的内容与实际执行的内容不是同一份」的时间窗
- 升级脚本新增无条件日志、进程退出等待（pid + 可执行文件双条件）与提权回退，失败时可从日志定位
- 升级前改为等待后台任务收敛后再退出，并加入 10 秒兜底退出，避免旧进程残留导致覆盖失败

## 安全加固

- FFmpeg 安装包固定到具体版本，并固定 SHA256 与文件大小、限制下载域名
- 压缩包解压前全量校验条目路径，含空名、绝对路径、盘符、UNC 或 `..` 穿越的包整包拒绝，不进行任何解压
- 解压后确认关键文件存在，缺失则不写入配置
- Node 运行时安装改为从官方 `SHASUMS256.txt` 读取哈希后校验
- DLNA 投屏中继新增访问控制：令牌绑定投屏设备地址、30 分钟有效期，停止投屏立即失效；令牌不存在、来源不符、已过期三种情况统一返回 404，不泄露令牌是否有效

## 稳定性

- 修复分离音视频投屏播放一段时间后卡死的问题 —— FFmpeg 的 stderr 管道写满后进程阻塞，现改为写入临时文件，失败时把尾部输出记入日志
- 修复快速翻页后部分封面永远停留在占位文字的问题 —— 已销毁控件抛出的异常不再中断同批其余等待者，等待者改用弱引用登记，不再泄漏包装对象
- 修复关闭窗口时偶发闪退或无响应 —— 退出顺序改为先终止下载子进程、等待线程池收敛，再释放投屏中继与 mpv；迟到的后台回调统一丢弃
- 修复视频解析成功但没有任何可用清晰度（会员限定、地区限制、临时断网等）时抛出 `StopIteration` 的问题，改为中文提示对话框

## 性能

- 文本折行改为按字符缓存宽度 + 增量累加，字体度量调用由 O(n²) 降到 O(n)，首页加载与窗口拉伸明显更顺畅
- 首页改为分批建卡（每批 12 张）并让出事件循环，封面改为随滚动按需加载，首屏立即可见，不再一次性发起数十个封面请求
- 播放列表只重绘状态真正发生变化的行，数百条列表的滚动与切歌不再掉帧
- 启动时只构建首页与播放页，播放列表 / 下载 / 收藏 / 历史 / 设置 / 关于六个页面改为首次进入时才创建

以上优化均以单元测试固定行为基线：折行结果、卡片数量与顺序、播放列表行状态在优化前后保持一致。

## 代理设置

- 新增代理模式三选一（自动 / 手动 / 强制直连），设置页显示当前实际生效的代理来源
- 修复用户在设置页显式填写的代理被系统代理静默覆盖的问题：自动模式下配置代理优先，手动模式不回退到系统代理，强制直连模式一律直连
- 修复 Bilibili 请求完全绕过代理设置的问题；关闭代理时也不再回落到 `http_proxy` 环境变量

## 测试

- 新增 `test_update_verify`、`test_archive_safety`、`test_dlna_access_control`、`test_dlna_media_server`、`test_text_elision`、`test_thumbnail_loading`、`test_main_window_hardening`、`test_ui_render_cost`、`test_proxy_settings` 等模块
- 全量单元测试 213 项通过，原有测试无回归
