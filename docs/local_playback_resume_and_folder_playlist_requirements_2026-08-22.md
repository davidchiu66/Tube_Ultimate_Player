# 本地播放记忆点与同目录播放列表需求分析、实施方案和验收标准

版本目标：`v0.2.28`  
编制日期：2026-08-22  
状态：**需求已审核通过，v0.2.28 已完成编码、回归测试和真实环境验证**

## 1. 需求范围

本批次包含三项能力：

1. 从「下载列表」播放已下载本地视频时，保存并恢复该文件的播放记忆点。
2. 从「历史播放」重新播放站点视频时，保存并恢复该视频的播放记忆点。
3. 从「下载列表」播放本地视频后，将该文件所在目录中的其他本地视频加载到播放器的「播放列表」中。

本批次不改变在线视频解析、站点合集/专辑层级、DLNA 投屏和现有已保存播放列表的语义。

## 2. 现状分析

### 2.1 播放入口

- 下载列表的完成任务通过 `DownloadPage.play_file_requested` 进入 `MainWindow.play_local_file()`。
- `play_local_file()` 当前只调用 `mpv.load(path)`，没有传入恢复位置，也没有创建本地播放队列。
- 历史播放页当前通过 URL 重新进入在线解析流程。

### 2.2 进度和历史

- `MpvPlayer` 已有 `position_changed`、`duration_changed` 和 `playback_finished` 信号，位置约每 500ms 被轮询。
- SQLite `history` 表已经有 `watched_position` 字段，但当前只在视频解析完成时由 `HistoryRepository.record_play(video)` 写入 `0`。
- 当前没有播放过程中定期更新历史位置的逻辑，也没有本地文件的记忆数据表。

### 2.3 播放列表

- 站点播放列表使用 `PlaylistInfo` / `PlaylistEntry`，点击条目后会再次通过 `ResolverWorker` 解析网页 URL。
- 本地文件没有网页 URL，不能直接套用站点解析流程。
- 因此本地目录列表应使用运行时本地队列，并在播放条目时直接调用 `mpv.load(local_path)`。

## 3. 推荐裁定

### A. 记忆点触发方式

采用**自动恢复 + 轻提示**：重新播放时自动跳转到记忆点，并显示一次短提示，例如「从 12:34 继续播放」。不增加强制确认弹窗，避免用户从历史页或下载列表连续播放时被打断。

### B. 记忆点有效区间

- 小于 5 秒的进度视为无效，按 0 秒播放。
- 已播放到总时长 95% 及以上视为完成，下次从 0 秒开始。
- 文件不存在、文件大小/修改时间发生变化且无法确认仍是同一媒体时，本地记忆点失效并清除。
- 用户点击「停止」时保留当前进度；视频自然播放结束时清零记忆点。

### C. 数据存储

- 在线视频：继续使用 `history.watched_position`，扩展历史仓储的读取和更新方法，不新增重复表。
- 本地视频：新增独立的 `local_playback_resume` 表，至少包含：规范化绝对路径、标题、文件大小、文件修改时间、播放位置、时长、最后更新时间。
- 本地记忆以规范化绝对路径为主键，不依赖下载任务 ID；即使下载任务列表刷新或任务 ID 变化，只要文件路径不变仍可恢复。
- 本地记忆不新增一条站点「历史播放」记录，避免历史页出现无法解析的 `file://` 项。

### D. 同目录视频范围和排序

- 只扫描当前文件的**直接父目录**，不递归子目录。
- 扫描常见视频扩展名：`mp4`、`mkv`、`webm`、`m4v`、`mov`、`avi`、`flv`、`wmv`、`ts`、`m2ts`。
- 忽略隐藏文件、目录、临时下载文件（`.part`、`.ytdl`、`.tmp`、`.temp`）和不存在的路径。
- 使用不区分大小写的自然排序，例如 `第2集` 排在 `第10集` 前；排序结果稳定且跨平台一致。
- 当前播放文件必须出现在列表中并定位为当前项；若扫描过程中当前文件不可读，则仍播放当前文件，但列表显示可用文件集合。
- 默认不自动连播，沿用现有播放列表默认关闭的行为；用户可在播放器列表面板中打开自动连播。

### E. 本地队列与现有站点队列的隔离

- 本地队列仅存在于当前播放会话，不写入 `playlist_library` / `playlist_item`。
- 本地队列条目增加本地路径字段，点击上一集/下一集或自动连播时直接本地加载，不经过 yt-dlp 解析。
- 从本地队列切换到站点视频时清理本地队列；从站点视频进入本地文件时清理站点播放列表和合集上下文。
- 小窗、全屏、清晰度、停止播放和窗口恢复逻辑继续复用现有播放器状态管理。

## 4. 实施方案

### 4.1 播放记忆服务/仓储

建议新增 `PlaybackResumeRepository`，或在现有数据库仓储层中增加等价职责：

- `get_online_position(video_id)` / `save_online_position(video_id, position, duration)`
- `get_local_position(path, stat)` / `save_local_position(path, position, duration, stat)`
- `clear_local_position(path)`
- 对位置、时长和文件元数据做数值归一化，防止负值、NaN 和异常大值写入数据库。

SQLite 初始化时通过 `CREATE TABLE IF NOT EXISTS` 创建新表，不影响既有数据库；旧版本升级无需手工迁移。

### 4.2 播放过程中的位置写入

- `MainWindow` 继续接收 mpv 的位置信号，但使用节流写入：位置变化达到约 5 秒，或距离上次写入超过约 5 秒时落盘。
- 暂停、停止、切换下一集、切换小窗/全屏、窗口关闭前强制 flush 一次。
- 站点视频按 `video_id` 更新历史位置；本地视频按规范化绝对路径更新本地记忆。
- 当前请求/当前媒体发生变化时，旧媒体的迟到位置信号不得写入新媒体。

### 4.3 恢复播放位置

- 在线视频解析完成后读取历史记忆，将有效位置传给 `mpv.load(..., start_position=position)`。
- 本地视频进入 `play_local_file()` 后读取本地记忆，将有效位置传给 `mpv.load(path, start_position=position)`。
- 恢复成功后显示一次轻提示；无有效记忆点时从 0 秒开始且不显示提示。
- 用户点击重新播放时显式清除当前媒体的记忆点并从 0 秒开始。

### 4.4 同目录本地播放列表

- 在 `play_local_file()` 中解析当前路径、扫描父目录并生成 `PlaylistInfo` 运行时对象及本地条目。
- 扩展本地条目模型，保存 `local_path`；站点条目的 `webpage_url` 语义保持不变。
- `MainWindow` 增加本地队列播放分支：本地条目直接调用本地加载方法，继承记忆点和窗口模式，不启动 `ResolverWorker`。
- `PlayerPage` 复用现有播放列表侧滑面板和上一集/下一集按钮，显示文件名；本地条目不显示站点来源和清晰度切换。
- 当前目录只有一个视频时仍显示播放列表入口，但列表只包含当前文件；目录扫描失败时保留当前视频播放，不阻塞起播。

### 4.5 下载列表和历史页交互

- 下载列表现有「播放」按钮无需新增入口，继续调用 `play_local_file()`，恢复逻辑在主窗口统一处理。
- 历史页现有「播放」按钮无需改变 URL 交互；在线解析完成后统一应用历史记忆点。
- 历史页可继续显示原有播放次数和最近播放时间；本批次不新增独立的「记忆点」列，避免表格过宽。

## 5. 异常和边界处理

- 记忆数据库损坏或单条记录异常时记录日志并按 0 秒播放，不阻塞视频播放。
- 同目录存在权限不可读、损坏或不支持的文件时跳过该文件并记录 debug 日志。
- 文件重命名后按新路径视为新媒体；不做基于哈希的全盘扫描，避免启动和播放延迟。
- 两个不同路径指向同一文件时，以规范化路径为准；本版本不追踪硬链接/符号链接的全局等价关系。
- 用户从历史页打开一个已被删除或不可解析的在线视频时，维持现有解析失败提示，不能因为读取记忆点失败而改变错误提示。

## 6. 验收标准

### 6.1 下载列表本地视频记忆点

1. 从下载列表播放一个本地视频，播放到 1 分钟后停止并再次播放，能够自动从接近 1 分钟处继续。
2. 关闭应用后重新启动，再从下载列表播放同一文件，记忆点仍然有效。
3. 播放到总时长 95% 以上自然结束，再次播放从 0 秒开始。
4. 点击重新播放后从 0 秒开始，并清除旧记忆点。
5. 删除、重建或重新加载下载任务列表不会导致同一路径的记忆点丢失。

### 6.2 历史播放记忆点

1. 从历史播放打开一个在线视频，播放到中途退出，再次从历史页打开，自动从有效记忆点继续。
2. 记忆点更新不会增加播放次数；播放次数仍按实际开始播放次数累计。
3. 同一视频从首页、搜索、历史或 URL 播放时共用同一记忆点。
4. 播放自然结束后再次从历史页打开，从 0 秒开始。
5. 解析失败、无清晰度或记忆数据库异常时，现有错误处理和正常播放不受影响。

### 6.3 同目录播放列表

1. 从下载列表播放某目录中的一个视频，播放器播放列表能看到该目录下所有支持格式的直接子文件。
2. 当前文件在列表中被正确定位，上一集/下一集切换直接播放对应本地文件，不触发网络解析。
3. 文件名按自然排序，`第2集` 排在 `第10集` 前；临时文件和子目录文件不出现。
4. 本地列表中的每个文件都能独立保存和恢复记忆点。
5. 开启自动连播后，本地视频按列表顺序连续播放；关闭时播放完当前文件即停止。
6. 从本地队列切换到在线视频后，站点合集/播放列表不混入本地条目；反向切换亦然。
7. 小窗、全屏、停止、窗口关闭和恢复主界面的既有行为不回归。

### 6.4 回归和质量门槛

- 新增仓储、位置节流、恢复加载、本地目录扫描、本地队列切换和边界条件测试。
- 全量自动化测试通过，`compileall` 和 `git diff --check` 通过。
- 至少完成 Windows 实际环境验收：下载列表本地文件、历史在线视频、关闭重启恢复、同目录混合格式列表和自动连播。
