# 播放器上一个/下一个控制需求分析、实施方案和验收标准

编制日期：2026-09-15

当前版本：`v0.2.31`

状态：**用户已审核通过，编码进行中**

## 1. 需求目标

在播放器底部控制器中增加“上一个”和“下一个”两个队列导航按钮，方便用户不打开播放列表滑窗也能切换视频。

用户需求：

1. 在“停止”按钮后面增加上一个 `◀`、下一个 `▶` 按钮；
2. 上一个快捷键为 `P`，下一个快捷键为 `N`；
3. 按钮点击和快捷键必须使用同一套播放切换逻辑；
4. 现有播放列表、合集列表、自动连播、播放记忆点、默认画质和小窗控制不应被破坏。

## 2. 现状分析

### 2.1 已有可复用能力

`ui/player_page.py` 已经存在：

- `playlist_entry_requested` 和 `collection_entry_requested` 信号；
- `_shortcut_playlist_step(delta)` 队列切换逻辑；
- 播放列表/合集当前索引和总数状态；
- 小窗控制器中的上一项、下一项按钮；
- 第一项/最后一项的边界判断；
- `PgUp` / `PgDown` 播放列表快捷键定义。

`ui/main_window.py` 已经存在：

- `_play_playlist_entry()` 和 `_play_collection_entry()`；
- 当前播放队列 `_active_queue`；
- 手动切换与自动连播的不同播放请求原因；
- 队列切换时的清晰度继承和播放窗口状态处理。

因此，本需求应扩展现有队列导航入口，不应复制解析、播放或连播逻辑。

### 2.2 当前逻辑需要统一的地方

现有键盘导航在“播放列表非空”时优先使用播放列表，只有播放列表为空时才使用合集；而自动连播使用 `_active_queue` 区分播放列表和合集。新增按钮如果直接复制任一侧逻辑，可能出现：

- 当前由合集驱动播放，但点击“下一个”却切到播放列表；
- 播放列表和合集同时存在时，按钮与自动连播方向不一致；
- 按钮禁用状态和快捷键实际是否可切换不一致。

本需求建议先抽出统一的“当前导航队列”判定，再由按钮、快捷键和小窗按钮共同调用。

## 3. 完善后的功能定义

### 3.1 控制器按钮

按钮顺序固定为：

```text
播放/暂停  停止  上一个  下一个  下载  收藏  ...
```

建议外观：

- 上一个显示 `◀`；
- 下一个显示 `▶`；
- 固定宽度，避免窗口尺寸变化时控制器抖动；
- 工具提示分别为“上一个（P）”和“下一个（N）”；
- 没有可切换队列、正在解析、无媒体、已停止或投屏不支持本地切换时禁用；
- 第一项禁用“上一个”，最后一项禁用“下一个”。

“停止”按钮的现有位置和行为不改变，新增按钮紧随其后。

### 3.2 快捷键

新增快捷键如下，原有 `PgUp` / `PgDown` 保留：

| 操作 | 默认键 | 说明 |
| --- | --- | --- |
| 上一个 | `P` | 与点击上一个按钮完全相同 |
| 下一个 | `N` | 与点击下一个按钮完全相同 |

原有 `PgUp` / `PgDown` 属于已有播放列表导航配置。为避免升级后用户自定义配置丢失，建议：

1. 新增 `previous_video` / `next_video`，默认值为 `P` / `N`；
2. 用户已经保存的自定义快捷键继续保留；
3. 设置页继续允许修改这两个快捷键；
4. `playlist_previous` / `playlist_next` 继续默认使用 `PgUp` / `PgDown`；
5. `P/N` 与 `PgUp/PgDown` 统一进入同一导航逻辑。

### 3.3 导航队列选择规则

统一按以下顺序确定导航队列：

1. 当前播放由合集驱动时，优先使用当前合集；
2. 当前播放由播放列表驱动时，优先使用当前播放列表；
3. 没有明确的当前播放来源时，播放列表优先；
4. 播放列表为空时使用合集；
5. 播放列表和合集都为空时，使用当前首页或搜索结果页的视频顺序；
6. 三类队列都为空时按钮禁用，快捷键无操作且不弹错误。

导航只在当前队列内移动，不跨越合集专辑边界，不循环回到第一项或最后一项。

### 3.4 播放切换状态

手动点击或按快捷键切换时：

- 使用现有队列播放入口；
- 继续保留上一个视频的清晰度继承规则；
- 继续保留播放记忆点、历史记录和收藏状态更新；
- 继续保留当前窗口/全屏/小窗会话状态；
- 切换过程中按钮暂时禁用，解析失败后恢复可操作状态；
- 不自动改变自动连播开关；
- 切换到新视频后及时更新当前索引和按钮禁用状态。

### 3.5 小窗模式

小窗已有上一项/下一项按钮。编码时应让其复用同一个统一导航方法，确保：

- 主控制器按钮、主窗口快捷键、小窗按钮行为一致；
- 队列边界判断一致；
- 小窗中切换不会意外退出小窗或恢复主窗口；
- 切换期间小窗控制器继续显示加载状态。

## 4. 实施方案

### 4.1 `PlayerPage`

1. 在播放控制器创建上一个、下一个按钮，插入停止按钮之后；
2. 新增按钮点击信号或统一导航请求入口；
3. 抽取 `_playlist_step_available(delta)` / `_request_queue_step(delta)` 等小方法，统一计算当前导航队列和边界；
4. 主控制器按钮、小窗按钮和快捷键都调用统一入口；
5. 在 `_update_playback_buttons()` 中同步更新两个主控制器按钮；
6. 播放列表、合集索引变化、加载状态变化、停止和清空上下文时都刷新按钮状态。

### 4.2 快捷键配置

1. 更新 `services/shortcut_service.py` 的默认值；
2. 更新 `config/default_config.json` 的默认值；
3. 保持已有用户配置优先，不覆盖用户已保存的快捷键；
4. 更新设置页显示文案和相关测试。

### 4.3 测试

增加以下测试：

- 控制器按钮创建、顺序和工具提示；
- 播放列表中间项可同时点击上一个和下一个；
- 第一项上一个禁用，最后一项下一个禁用；
- 只有合集时按钮和快捷键操作合集；
- 播放列表与合集同时存在时按当前活动队列优先；
- 无队列、无媒体、加载中时按钮和快捷键均不触发播放请求；
- 主控制器、小窗控制器和快捷键得到同一目标索引；
- 用户自定义快捷键不会被默认值升级覆盖；
- 全量测试、编译检查和 Ruff 检查通过。

## 5. 验收标准

### A. 控制器布局

- [ ] 播放器控制器中“上一个”“下一个”位于“停止”之后；
- [ ] 两个按钮在普通窗口、全屏和小窗相关状态下布局稳定，不遮挡现有控件；
- [ ] 按钮有清晰的 `◀` / `▶` 图标和中文工具提示。

### B. 播放列表切换

- [ ] 播放列表有多条视频时，点击上一个/下一个可切换到相邻视频；
- [ ] 第一条视频不能继续上一个，最后一条视频不能继续下一个；
- [ ] 边界点击不会循环播放，也不会弹出错误对话框；
- [ ] 切换时当前索引、列表高亮和按钮状态同步更新。

### C. 合集切换

- [ ] 当前仅有合集时，两个按钮可以切换合集中的相邻视频；
- [ ] 当前播放由合集驱动且播放列表同时存在时，按钮优先操作合集；
- [ ] 跨专辑边界的行为与现有合集自动连播规则一致，不误切入下一专辑。

### D. 快捷键

- [ ] 默认按 `P` 等价于点击上一个；
- [ ] 默认按 `N` 等价于点击下一个；
- [ ] 输入框、搜索框获得焦点时，快捷键不会抢占文字输入；
- [ ] 设置页可查看和修改这两个快捷键；
- [ ] 已有用户自定义快捷键升级后保持不变。

### E. 播放连续性

- [ ] 手动切换继续继承上一个视频的清晰度策略；
- [ ] 播放记忆点、播放历史、收藏和窗口模式行为不回退；
- [ ] 解析失败时不会改变当前已播放视频的状态，按钮可继续使用；
- [ ] 小窗按钮、主控制器按钮和快捷键的行为完全一致。

## 6. 风险与降级

1. 当前队列正在解析时，按钮必须禁用，避免并发解析覆盖当前播放请求；
2. 站点视频列表异步加载未完成时，按钮只按已确认的条目数判断，不猜测下一项；
3. 如果当前视频不属于任何播放列表或合集，按钮保持禁用，快捷键静默无操作；
4. 快捷键默认值升级不能覆盖已有用户配置；
5. 不新增独立播放状态机，避免与现有自动连播、停止、全屏和小窗逻辑分叉。
