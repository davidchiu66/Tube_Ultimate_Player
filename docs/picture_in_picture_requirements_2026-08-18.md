# 小窗播放需求分析与实施方案（v0.2.27）

日期：2026-08-18  
状态：**需求已裁定并定稿，v0.2.27 已完成编码与回归验证**

## 1. 目标

为本地播放器增加轻量的小窗播放模式，使用户在处理其他工作时仍能持续观看视频。

本需求包含：

1. 播放控制面板在「全屏」按钮后增加「小窗」按钮。
2. 默认快捷键为 `W`，按钮和快捷键均用于进入/退出小窗模式。
3. 小窗以视频画面为主体，并提供轻量标题栏、悬浮按钮和迷你控制条；支持拖动、等比例缩放、置顶、单击播放/暂停和双击退出。
4. 退出小窗后完整恢复进入前的窗口状态，播放流不中断、不重新解析、不重新加载。

目标版本：`0.2.27`。

---

## 2. 当前实现核实

### 2.1 播放器结构

- `ui/player_page.py` 中的 `PlayerPage.video_widget` 是带 `WA_NativeWindow` 的原生 `QFrame`。
- `player/mpv_player.py` 初始化时把 `video_widget.winId()` 写入 libmpv 的 `wid`，之后 mpv 持续向这个原生窗口句柄输出画面。
- 控制面板、播放列表和合集列表都是 `PlayerPage` 上的浮层；视频控件本身是页面主布局中唯一占伸缩空间的控件。

因此不建议创建第二个顶层窗口后再迁移 `video_widget`。原生控件跨顶层窗口重新挂载可能导致 WinId 或底层 HWND/X11 Window 重建，进而出现黑屏、视频输出丢失或平台差异。

本方案采用：**现有主窗口临时切换为无边框、仅视频、强制置顶的小窗**。视频控件不换父对象，libmpv 不重载，播放状态天然保持。

### 2.2 现有交互可复用点

- 控制面板已经有「投屏」「全屏」按钮和统一信号连接。
- 快捷键由 `services/shortcut_service.py` 统一定义，可在设置页查看、修改、禁用并进行冲突检查。
- 视频画面单击已经通过 220ms 定时器区分单击和双击：单击播放/暂停，双击切换全屏。
- 主窗口已有全屏进入/退出、最大化状态恢复和用户手动置顶逻辑。
- 停止播放时会自动退出全屏并返回播放前页面。

### 2.3 必须处理的现有限制

- 主窗口正常模式最小尺寸目前为 `640 x 420`，视频控件最小高度为 `360`，两者都会阻止 `320 x 180` 小窗，进入小窗时必须临时解除，退出时恢复。
- 全屏、用户置顶和小窗强制置顶是三个不同概念，不能共用一个布尔值，否则退出小窗可能错误清除用户原有的置顶设置。
- 小窗默认无系统标题栏，需要自行实现轻量标题栏、悬浮控制层、拖动、边缘/四角缩放、鼠标指针和尺寸约束。
- 单击暂停、双击退出、拖动窗口和缩放窗口都发生在同一个视频表面，需要建立明确的手势优先级。

## 3. 完善后的功能需求

### 3.1 入口与可用状态

1. 在播放控制面板「全屏」按钮之后增加「小窗」按钮，文字为「小窗」，工具提示为 `小窗播放（W）`。
2. 快捷键动作名为 `picture_in_picture`，默认键为 `W`。
3. `W` 是切换键：普通/全屏模式下进入小窗，小窗模式下退出并恢复原状态。
4. 快捷键继续纳入设置页统一管理，允许用户改键或清空禁用；输入框获得焦点时仍按现有规则暂停播放器快捷键。
5. 只有媒体已成功加载且不处于加载状态时允许进入小窗。
6. DLNA 投屏期间不允许进入小窗：本地视频输出可能已暂停或没有有效画面，此时按钮禁用；若通过快捷键触发则忽略并显示简短提示。
7. 小窗模式中控制面板隐藏，因此退出入口为 `W`、`Esc` 或双击画面。

### 3.2 小窗视觉状态

进入小窗后：

- 主窗口切换为无边框窗口，但小窗内部提供应用自绘的轻量标题栏和悬浮控制层。
- 视频画面占据主体区域，视频区域与窗口四边之间无固定布局留白。
- 顶部工具栏、常规播放控制面板、播放列表浮层、合集浮层和中屏快捷键提示不显示。
- 窗口强制置顶，任务栏/程序坞中的应用身份保持不变，不额外创建第二个播放器窗口。

### 3.2.1 小窗标题栏

标题栏位于视频区域顶部，默认高度 32px，使用半透明深色背景：

- 左侧显示当前视频标题，过长时单行省略；标题为空时显示「正在播放」。
- 标题栏空白区域支持拖动窗口。
- 右侧提供「退出小窗」按钮和关闭按钮 `×`；两者均退出小窗并恢复进入前的窗口状态，不停止播放、不关闭应用。
- 关闭按钮不执行 `mpv.stop()`；应用关闭仍使用系统 `Alt+F4` 或主窗口关闭流程。
- 标题栏按钮属于控制区域，不参与画面单击暂停、双击退出和窗口拖动判定。

### 3.2.2 悬浮迷你控制条

控制条位于视频区域底部，默认高度约 48px，使用半透明深色背景，悬浮覆盖视频而不改变视频有效画面尺寸。按从左到右的顺序提供：

1. 播放/暂停按钮；
2. 上一集、下一集按钮（无可用队列时禁用）；
3. 可拖动进度条与当前时间/总时长；
4. 静音按钮和音量滑块；
5. 全屏按钮；
6. 退出小窗按钮。
7. 锁定/解锁按钮；默认不锁定，锁定后禁止移动和缩放窗口，但其他播放控制仍可使用。

清晰度、音轨、字幕、倍速、下载、收藏、投屏等低频或空间占用较大的功能继续通过键盘快捷键或退出小窗后的常规控制面板完成，不在首版迷你控制条中展开下拉菜单。

控制条按钮应复用项目已有图标/按钮风格，并为不熟悉的图标提供工具提示。按钮点击只执行对应操作，不触发画面暂停、窗口拖动或双击退出。

### 3.2.3 悬浮层显示规则

- 进入小窗后标题栏和控制条默认显示 3 秒，随后自动淡出。
- 鼠标移动到视频区域、标题栏或控制条时立即显示；鼠标位于控制层内时不自动隐藏。
- 鼠标停止移动 3 秒且不处于按钮、滑块交互中时再次淡出。
- 控制层淡出只改变可见性和透明度，不改变视频窗口尺寸、宽高比或拖动/缩放边界。
- 加载、切集、播放失败或显示快捷键提示时，控制层可临时保持显示，避免用户看不到状态反馈。
- 单击视频背景切换播放状态后，在画面中央显示 `▶ 播放` 或 `⏸ 暂停` 提示，1 秒后自动消失；拖动、缩放、双击和控制条按钮操作不触发该提示。

### 3.3 进入与退出状态恢复

进入前保存以下状态：

- 正常、最大化或全屏状态；
- 正常窗口几何位置和尺寸；
- 是否为用户主动置顶；
- 当前堆栈页面和顶部工具栏可见状态；
- `PlayerPage` 的全屏视觉状态；
- 主窗口与视频控件的最小/最大尺寸约束；
- 小窗前已经展开的播放列表/合集浮层状态。

退出后：

- 从普通窗口进入：恢复原位置和尺寸。
- 从最大化进入：恢复最大化。
- 从全屏进入：恢复全屏，并保留原有的全屏退出目标；之后再按 `Esc` 仍能正确回到全屏前的普通/最大化状态。
- 进入前用户已开启置顶：退出后继续置顶；进入前未置顶：退出后取消小窗强制置顶。
- 返回播放器页面并恢复常规控制面板逻辑。
- 恢复进入小窗前标题栏/迷你控制条不再参与常规页面布局。
- 不重新解析 URL，不重新调用 `mpv.load()`，播放位置、暂停状态、清晰度、音轨、字幕、速度和音量保持不变。

为避免退出时界面突然出现两个侧栏，进入小窗时若播放列表或合集浮层已展开，只记录其状态；退出后恢复原先展开的那一个。

### 3.4 播放结束与停止

- 视频自然播放结束且没有自动连播下一集时，保持小窗和最终画面，并显示轻量结束层。
- 结束层提供「重新播放」和「返回播放器」两个按钮；不再增加与返回行为重复的第三个「关闭窗口」按钮。
- 「重新播放」沿用现有重播逻辑；「返回播放器」退出小窗并恢复原窗口状态。
- 自动连播下一集时保持小窗，不做窗口模式切换。
- 用户执行「停止」、播放加载失败或媒体被清空时，自动退出小窗并恢复主界面，再沿用现有停止后的返回逻辑。
- 应用关闭时不需要先显示主窗口；直接完成现有资源清理并退出，播放不会在独立进程中继续。

## 4. 尺寸与宽高比规则

### 4.1 宽高比来源

优先使用 libmpv 当前画面属性 `video-params/aspect`，因为它包含实际视频画面、旋转和 mpv 识别后的显示比例。

回退顺序：

1. libmpv 当前有效画面比例；
2. 当前 `video_widget` 的宽高比；
3. `16:9`。

比例异常、为 0、NaN、无穷或超出合理范围时使用 `16:9`。

自动连播到不同比例的视频时，保持小窗中心点和当前宽度，重新计算高度；若超出目标屏幕限制则整体缩小。

### 4.2 最小尺寸

用户给定的最小边界是 `320 x 180`。为同时满足真实画面比例：

- 小窗宽度不得小于 320；
- 小窗高度不得小于 180；
- 最终尺寸必须保持视频比例。

因此 16:9 视频的最小尺寸是 `320 x 180`，4:3 视频是 `320 x 240`，竖屏视频则以宽度 320 为下限并按比例增加高度。

### 4.3 最大尺寸

最大尺寸按小窗所在屏幕的可用工作区动态计算：

```text
最大宽度 = min(可用工作区宽度 x 50%, 1920)
最大高度 = min(可用工作区高度, 1080)
```

随后把当前视频比例等比适配进这个最大边界框。

这样在 1920 宽屏幕上，16:9 小窗最大约为 `960 x 540`；在 3840 宽屏幕上最大为 `1920 x 1080`。任务栏、Dock 等占用区域由 `availableGeometry()` 自动扣除。

当极小工作区导致「最大宽度小于最小宽度」时，优先保证窗口可见并取工作区可容纳的最大等比尺寸；这是无法同时满足两个硬约束时的唯一降级分支。

### 4.4 初始位置和尺寸

- 首次进入采用不超过 `640 x 360` 的等比尺寸，并受上述最小/最大边界约束。
- 初始显示在当前主窗口所在屏幕的右下角，距工作区边缘 24px。
- 持久化用户最后一次小窗尺寸、坐标和静音状态，再次启动应用时优先恢复。
- 恢复持久化几何前必须执行显示器有效性、工作区和当前视频比例校验；无法映射到任何当前屏幕时回退到当前屏幕右下角默认位置。
- 配置写入 `player.picture_in_picture`，不把显示器设备名作为必须匹配的硬依赖。

### 4.5 多显示器与 DPI

- 使用 Qt 的逻辑像素计算尺寸，不自行乘除设备像素比。
- 拖到另一显示器后，以鼠标释放位置所在屏幕重新计算最大尺寸并夹取到目标工作区。
- 若原小窗尺寸超过新屏幕允许值，释放后等比缩小；不超过则保持用户尺寸。
- 窗口至少完整位于一个屏幕工作区内，不允许退出后遗留一个无法拖回的窗口。

### 4.6 边缘吸附

- 拖动结束时，若小窗任一边距离目标屏幕可用工作区对应边缘小于 20px，则吸附到该边缘。
- 横向和纵向可同时吸附，因此靠近角落时可吸附到屏幕角。
- 吸附只调整位置，不改变窗口尺寸、宽高比或锁定状态。
- 小窗锁定时不允许拖动，因此不会触发新的吸附；已吸附位置保持不变。

## 5. 鼠标与键盘交互

### 5.1 手势优先级

按以下优先级处理左键操作：

1. 命中窗口边缘或四角：缩放。
2. 命中标题栏空白区域并按住后移动距离达到 `QApplication.startDragDistance()`：拖动窗口。
3. 命中视频背景并按住后移动距离达到阈值：拖动窗口。
4. 命中视频背景且未达到拖动阈值并释放：候选单击，延迟 220ms 后切换播放/暂停。
5. 220ms 内在视频背景收到双击：取消候选单击，退出小窗，不改变暂停状态。
6. 命中标题栏按钮、迷你控制条、进度条或音量滑块：只执行控件自身操作，不触发上述手势。

这样拖动或缩放不会误触暂停，双击退出也不会先暂停再恢复。

### 5.2 拖动

- 视频背景和标题栏空白区域可以拖动；标题栏按钮、迷你控制条、进度条和音量滑块不参与拖动。
- 按下时记录全局鼠标位置与窗口起点，移动时更新窗口位置。
- 松开时判断目标屏幕，先做最终可见性夹取，再按 20px 阈值执行边缘吸附。
- 锁定状态下忽略标题栏和视频背景的拖动手势，不改变窗口位置。
- 右键、中键和滚轮不用于拖动；滚轮继续沿用现有音量调节。

### 5.3 等比例缩放

- 四边和四角提供 8px 逻辑像素的不可见缩放热区。
- 鼠标进入热区时显示对应的水平、垂直或对角缩放指针。
- 拖动某条边时，以对边中心为锚点；拖动角时，以对角为锚点。
- 根据鼠标主移动方向计算候选宽度或高度，再用视频比例推导另一边。
- 每次更新都经过最小值、最大值和目标屏幕工作区约束。
- 窗口比例变化只调整几何尺寸，不改变视频播放或重新载入流。
- 锁定状态下边缘和四角不进入缩放指针，也不响应缩放拖动。

### 5.4 快捷键行为

- `W`：进入/退出小窗。
- `Esc`：小窗中退出小窗；非小窗时继续只负责退出全屏。
- `Enter/Return`：小窗中先恢复原窗口，再进入全屏；普通模式维持现有全屏切换行为。
- `Left/Right`：继续沿用全局后退/前进 10 秒；小窗不单独改为 5 秒。
- `Space`、音量、速度、静音、上一集/下一集等既有快捷键在小窗中继续有效。
- 编辑控件获得焦点时快捷键禁用规则不变；小窗中没有编辑控件，因此 `W` 可正常使用。

## 6. 状态模型与实现方案

### 6.1 状态快照

建议在 `ui/main_window.py` 定义内部数据结构：

```python
@dataclass
class PictureInPictureSnapshot:
    geometry: QRect
    normal_geometry: QRect
    window_state: Qt.WindowState
    window_flags: Qt.WindowFlags
    was_fullscreen: bool
    was_maximized: bool
    was_topmost: bool
    top_bar_visible: bool
    stack_widget: QWidget
    playlist_overlay_visible: bool
    collection_overlay_visible: bool
    minimum_size: QSize
    maximum_size: QSize
```

主窗口新增：

```text
_picture_in_picture = False
_picture_in_picture_snapshot = None
_last_picture_in_picture_geometry = QRect()
_picture_in_picture_aspect = 16 / 9
_picture_in_picture_locked = False
```

小窗状态独立于 `isFullScreen()` 和 `_is_topmost`，避免三个窗口模式互相污染。

### 6.2 主窗口职责

建议新增方法：

```text
_toggle_picture_in_picture()
_enter_picture_in_picture()
_leave_picture_in_picture(target_mode="restore")
_apply_picture_in_picture_flags()
_update_picture_in_picture_aspect(aspect)
_picture_in_picture_screen(...)
```

主窗口负责：

- 快照和恢复窗口状态；
- 切换无边框/置顶窗口标志；
- 设置和恢复窗口最小/最大尺寸；
- 处理拖动和缩放后的窗口几何；
- 处理边缘吸附、锁定状态和持久化几何恢复；
- 协调全屏、停止播放、DLNA 和关闭流程。

### 6.3 PlayerPage 职责

新增信号：

```text
picture_in_picture_requested
picture_in_picture_drag_started / moved / finished
picture_in_picture_resize_started / moved / finished
```

也可以把移动/缩放合并为一个带动作类型的数据结构信号，避免主窗口直接读取私有手势状态。

新增 `set_picture_in_picture(enabled)`：

- 更新内部 `_picture_in_picture`；
- 隐藏或恢复控制面板和两侧浮层；
- 布局边距切为 0 或恢复 16；
- 临时解除 `video_widget` 的 360px 最小高度；
- 双击画面在小窗中发出退出小窗信号，非小窗时继续切换全屏；
- 构建标题栏、迷你控制条、1 秒播放状态提示和播放结束层；
- 锁定时更新锁定按钮状态并禁用拖动/缩放手势；
- 进入小窗后禁用控制面板自动隐藏动画，避免隐藏控件仍参与布局/动画；
- 退出后恢复鼠标指针、自动隐藏定时器和控制面板定位。

### 6.4 MpvPlayer 职责

新增：

```text
video_aspect_changed = Signal(float)
video_aspect_ratio() -> float
```

在现有 500ms 属性轮询中读取 `video-params/aspect`，仅在有效值发生明显变化时发信号。小窗外收到信号只缓存，不调整主窗口；小窗内收到信号才等比更新窗口。

### 6.5 纯几何辅助模块

建议新增 `ui/picture_in_picture.py`，只放不依赖真实窗口的纯函数和数据类型：

```text
normalized_aspect(...)
minimum_size_for_aspect(...)
maximum_size_for_screen(...)
constrain_size(...)
initial_geometry(...)
resize_geometry(...)
clamp_geometry_to_screen(...)
snap_geometry_to_edges(...)
PictureInPictureResizeEdge
```

几何算法从事件处理器中分离后，可以离屏单测所有比例、边缘、屏幕和 DPI 边界，不依赖真实 mpv。

## 7. 与现有功能的协调

### 7.1 全屏

- 小窗和全屏互斥。
- 从全屏进入小窗时保留全屏快照，不调用会丢失上下文的普通退出流程。
- 小窗中请求全屏时，先结束小窗状态，再进入全屏。
- 停止播放统一先退出小窗/全屏，再执行现有返回逻辑。

### 7.2 置顶

- 小窗强制添加 `WindowStaysOnTopHint`，但不修改用户偏好字段 `_is_topmost`。
- 退出小窗后按进入前的用户置顶状态恢复，并同步顶部工具栏按钮。

### 7.3 播放列表与合集

- 自动连播、手动下一集和画质继承逻辑不受影响。
- 小窗中不显示左右侧列表，但迷你控制条和 `PgUp/PgDown` 仍可按当前活动队列切集。
- 新视频比例变化时按第 4.1 节调整小窗尺寸。

### 7.4 本地播放与在线播放

- 两者都由同一个 mpv 视频表面播放，均支持小窗。
- 小窗不改变解析、Cookie、代理、智能画质和下载行为。

### 7.5 DLNA

- 远端投屏激活或正在建立连接时，小窗按钮禁用。
- 已在小窗中发起投屏的入口不可见，但仍需在主窗口处理函数增加守卫：若未来通过快捷键或其他入口发起投屏，先退出小窗再打开投屏流程。

## 10. 自动化测试计划

### 10.1 几何纯函数

1. 16:9 最小尺寸为 `320 x 180`。
2. 4:3 最小尺寸为 `320 x 240`。
3. 竖屏比例满足宽高下限且不变形。
4. 1920 宽工作区的 16:9 最大尺寸为 `960 x 540`。
5. 3840x2160 工作区最大不超过 `1920 x 1080`。
6. 工作区高度不足时按高度反向限制宽度。
7. 左、右、上、下和四角缩放均保持比例且固定正确锚点。
8. 小于最小值、超过最大值和异常比例均正确夹取。
9. 拖到第二屏后采用第二屏边界。
10. 保存的小窗位置失效时回退到当前屏幕右下角。
11. 距离任一边缘小于 20px 时正确吸附，角落可同时吸附两条边。
12. 锁定状态下几何函数不会接收移动或缩放更新。

### 10.2 PlayerPage 交互

1. 「小窗」按钮位于「全屏」之后。
2. `W` 被注册且可由配置覆盖或禁用。
3. 无媒体/加载中不发出小窗请求。
4. 小窗单击只发一次播放/暂停。
5. 小窗双击只发退出请求，不发播放/暂停，也不发全屏请求。
6. 拖动超过阈值不发播放/暂停。
7. 边缘缩放不发播放/暂停或窗口拖动。
8. 滚轮仍调音量。
9. 进入小窗隐藏常规控制面板和侧栏，显示标题栏与迷你控制条，退出恢复。
10. `Esc` 在小窗中退出，在普通模式不误触。
11. 标题栏与迷你控制条自动隐藏、移动鼠标后显示，控件交互期间不消失。
12. 标题栏关闭按钮只退出小窗，不停止媒体或关闭应用。
13. 单击背景显示 1 秒播放/暂停提示，双击和拖动不显示。
14. 播放结束层仅显示「重新播放」「返回播放器」，自动连播时不显示。
15. 锁定后不能拖动或缩放，解锁后立即恢复。

### 10.3 主窗口状态

1. 普通窗口进入/退出后几何位置和尺寸一致。
2. 最大化进入/退出后恢复最大化。
3. 全屏进入/退出后恢复全屏，再退出全屏仍回到正确的普通/最大化状态。
4. 原本未置顶：小窗置顶，退出后不置顶。
5. 原本已置顶：退出后仍置顶。
6. 进入小窗不调用 `mpv.load()`，位置和暂停状态不变。
7. 自动连播保持小窗。
8. 停止播放自动退出小窗并执行原返回逻辑。
9. DLNA 活跃时拒绝进入小窗。
10. 视频比例变化时窗口等比更新且不超屏幕边界。
11. 几何与静音状态保存后重启可恢复，失效坐标安全回退。
12. 连续进入/退出 100 次不崩溃、不重载媒体、无明显资源泄漏。

## 11. 人工验收标准

### 11.1 入口和基础行为

1. 播放视频后，控制面板「全屏」后面显示「小窗」按钮。
2. 点击按钮或按 `W` 均能进入小窗；再次按 `W` 能退出。
3. 设置页快捷键列表显示「小窗 / 退出小窗」，默认 `W`，可修改、禁用并参与冲突校验。
4. 未播放视频、解析中和 DLNA 投屏中不能进入小窗。

### 11.2 视觉与置顶

1. 小窗中只显示视频画面及轻量标题栏、迷你控制条，没有常规顶部工具栏、封面、详情区或左右列表。
2. 标题栏显示当前视频标题，过长时不撑破布局；右侧有退出小窗和关闭按钮。
3. 迷你控制条包含播放/暂停、队列切换、进度、音量、全屏、退出小窗和锁定控件。
4. 小窗始终位于普通应用窗口之上。
5. 切换到其他程序后视频持续正常播放。
6. 退出小窗后，进入前未置顶的主窗口不再置顶；进入前已置顶的仍保持置顶。

### 11.3 拖动和缩放

1. 在画面任意非边缘位置按住左键可平滑拖动。
2. 四边和四角可缩放，鼠标指针方向正确。
3. 任意缩放过程中画面不拉伸，窗口比例与实际视频比例一致。
4. 16:9 视频不能小于 `320 x 180`。
5. 1920 宽屏幕上不能超过约 `960 x 540`；4K 屏幕上不能超过 `1920 x 1080`。
6. 拖到不同 DPI/分辨率的第二屏后仍可正常缩放，不会跑出工作区或消失。
7. 首次进入默认位于当前屏幕右下角；拖到距离边缘 20px 内时正确吸附。
8. 锁定后不能拖动或缩放，播放控制不受影响；解锁后恢复正常。

### 11.4 播放交互

1. 单击画面切换暂停/播放，每次只切换一次。
2. 双击视频背景退出小窗，不能额外触发暂停，也不能直接进入全屏。
3. 点击标题栏退出/关闭按钮只退出小窗，不停止播放或关闭应用。
4. 点击迷你控制条的播放、队列、进度、音量和全屏控件只执行对应操作。
5. 拖动和缩放不会误触暂停；在控制条上拖进度不会拖动窗口。
6. 滚轮音量、Space、静音、倍速、上一集和下一集快捷键继续工作；左右方向键保持 10 秒跳转。
7. 自动连播时不退出小窗，下一集比例变化时窗口自动保持正确比例。
8. 单击播放/暂停后中屏提示显示约 1 秒，不遮挡后续操作。
9. 播放自然结束时显示「重新播放」「返回播放器」，自动连播成功时不显示结束层。

### 11.5 状态恢复

1. 普通窗口进入小窗后退出，恢复原位置、尺寸和播放页。
2. 最大化窗口进入小窗后退出，恢复最大化。
3. 全屏进入小窗后退出，恢复全屏；随后按 `Esc` 能回到全屏前状态。
4. 小窗进入、退出期间视频不黑屏、不重新缓冲、不跳回开头，清晰度、音轨和字幕不变。
5. 小窗中停止播放，自动恢复主界面并返回原页面。
6. 小窗中按 `Alt+F4` 可正常关闭应用，无残留进程。
7. 调整小窗位置、尺寸和静音后重启应用，再次进入小窗时正确恢复；显示器变化时不会恢复到屏幕外。

### 11.6 回归与平台

1. 原有全屏按钮、Enter/Return、Esc 和双击全屏行为在非小窗模式下不退化。
2. 原有用户置顶按钮不退化。
3. Windows 安装版和便携版各完成一次在线视频与本地视频验收。
4. Fedora X11 完成一次进入、拖动、缩放和退出验收；Wayland 仍沿用项目当前不支持原生嵌入 mpv 的边界。
5. 全量单元测试、`compileall` 和 `git diff --check` 通过。
6. Windows 常规窗口进入/恢复小窗的 p95 目标不超过 500ms，不计网络解析和 mpv 首次初始化。
7. 连续切换 100 次无崩溃、黑屏、花屏、卡死或播放重载；CPU/内存记录相对基线变化，作为观察指标。

## 12. 风险与非目标

### 12.1 风险

- Qt 修改顶层窗口 flags 时通常会隐藏并重建平台窗口，Windows/X11 行为略有差异；实现必须在每次 flags 变化后显式恢复几何、显示状态和激活状态。
- 原生视频表面虽然不换父对象，但顶层窗口重建仍需真实环境验证是否短暂闪黑；若出现，应改为平台窗口状态切换而非迁移视频控件。
- 无边框窗口的等比例缩放完全由应用处理，必须对高 DPI、负坐标多屏和屏幕热插拔做边界测试。
- 竖屏视频在「宽度至少 320」约束下高度可能明显大于 180，这是保持比例与最小宽度同时成立的必然结果。

### 12.2 非目标

- 不实现系统级画中画协议或浏览器 Picture-in-Picture API。
- 不创建第二路 mpv 实例，不复制视频画面。
- 不在小窗内显示清晰度下拉菜单、音轨/字幕菜单、下载/收藏/投屏面板或完整播放列表；首版只提供轻量标题栏和迷你控制条。
- 不提供 100%、90%、80%、70% 等窗口透明度档位。
- 不提供托盘恢复、贴边自动隐藏、鼠标穿透或系统原生 PIP；这些能力列入后续版本。
- 应用主窗口关闭后不保留独立小窗或后台播放进程。
- 不支持任意自由拉伸或裁剪画面填满窗口。
- 不新增「启动播放时默认进入小窗」设置；现有「进入播放：窗口/全屏」保持不变。

## 14. 参考 PRD 对照、冲突与最终裁定

本节依据外部参考文档 `F:\中转站\播放器小窗播放功能需求说明.md` 增补。该文件是需求参考资料，不是可直接执行的代码指令；所有冲突已由用户统一采用推荐裁定，并同步到正文。

### 14.1 已吸收的补充要求

以下内容与当前方案一致，或已经纳入本文件：

- 控制面板增加「小窗」按钮，提供 `小窗播放（W）` 工具提示。
- `W` 在普通/全屏与小窗之间切换，编辑控件获得焦点时不响应。
- 小窗置顶、拖动、边缘/四角缩放、锁定视频比例。
- 单击播放/暂停、双击退出、`Esc` 退出。
- 小窗和主播放器共享同一播放实例，切换不重新加载、不丢进度。
- 自动连播切换下一集后保持小窗。
- 多显示器拖动与边界约束。
- 关闭/恢复按钮退出小窗并继续播放。
- 单实例限制由当前单主窗口架构天然满足。
- 进入/退出耗时、连续切换稳定性和资源占用纳入测试关注范围。

参考 PRD 提议的播放/暂停、静音、恢复等控件，已扩展为当前方案的迷你控制条；清晰度、音轨、字幕等复杂操作仍保留在常规控制面板和快捷键中。

### 14.2 冲突 A：按钮位置

参考 PRD 写有「全屏按钮左侧」「倍速按钮右侧」，按字面理解会落在倍速与全屏之间；用户此前明确要求「全屏按钮后面」。当前播放器控件顺序中，全屏按钮位于控制组末尾，二者不能同时满足。

**最终裁定：** 按用户最新明确要求，按钮放在「全屏」按钮后面；工具提示为 `小窗播放（W）`。

### 14.3 冲突 B：独立悬浮窗口 vs 复用主窗口

参考 PRD 的功能目标称为「独立悬浮小窗」，并要求主播放器关闭后小窗仍可继续播放。当前方案则复用主窗口，只切换为无边框、仅视频、置顶状态，原因是 libmpv 在初始化时绑定了现有原生视频控件的窗口句柄，迁移到第二个顶层窗口存在黑屏和句柄重建风险。

**最终裁定 B1：** v0.2.27 采用复用主窗口的视觉小窗模式，不创建第二个 mpv 或第二个播放进程；应用主窗口关闭时播放随应用关闭。主窗口关闭后独立播放不纳入本版本。

### 14.4 冲突 C：小窗是否显示标题栏和控制层

参考 PRD 3.1 的旧文字要求隐藏标题栏和播放控制栏；用户最新补充明确要求小窗增加悬浮按钮、标题栏、关闭按钮或迷你控制条。

**最终裁定：** 以用户最新指令覆盖参考 PRD 的极简显示条款，采用本文件 3.2 的轻量标题栏和迷你控制条。标题栏是应用自绘层，不恢复系统原生窗口边框。

### 14.5 冲突 D：方向键快进步长

参考 PRD 要求左右方向键后退/前进 5 秒；当前播放器既有快捷键和既有验收口径是 10 秒，且 `Ctrl+Left/Right` 已用于 60 秒跳转。

**最终裁定 D1：** 保持现有全局行为：方向键仍为 10 秒，小窗不单独改变步长，避免同一快捷键在不同模式产生不一致。

### 14.6 补充 E：单击反馈

参考 PRD 要求单击后显示 `▶ 播放` 或 `⏸ 暂停`，约 1 秒后消失。当前方案只定义了播放状态切换，没有明确中屏反馈。

**最终裁定：** 增加小窗专用短暂状态提示，显示在视频中央但不改变窗口尺寸；显示时长 1 秒，双击、拖动、控制条点击不重复触发。提示复用现有 `shortcut_hint` 的视觉机制或抽取为通用提示组件。

### 14.7 补充 F：播放结束状态

参考 PRD 要求结束时显示「重新播放」「关闭窗口」「返回播放器」；当前方案要求自然结束时保留小窗最终画面，单击可重播，`W`/`Esc`/双击可退出。

**最终裁定 F1：** 播放结束时显示轻量结束层，提供「重新播放」和「返回播放器/退出小窗」两个明确按钮；不增加第三个与“返回播放器”重复的“关闭窗口”按钮。自动连播成功时不显示结束层。

### 14.8 冲突 G：小窗几何和静音是否跨重启保存

参考 PRD 要求保存小窗大小、坐标和静音状态，并在下次优先恢复；当前方案只在本次运行期间记忆，避免显示器/DPI 变化造成窗口不可见。

**最终裁定 G1：** 持久化小窗尺寸、位置和静音状态，但恢复时必须经过显示器有效性校验、工作区夹取和当前比例约束；校验失败则使用当前屏幕默认位置。配置写入 `player.picture_in_picture`，不保存屏幕设备名作为硬依赖。

### 14.9 补充 H：右下角默认位置与边缘吸附

参考 PRD 推荐首次进入位于屏幕右下角，并建议距离边缘小于 20px 时自动吸附；裁定前草案原为右上角、24px 边距，且未定义吸附。

**最终裁定 H1：** 默认位置改为当前屏幕右下角、24px 边距；拖动结束时若距离任一工作区边缘小于 20px，则吸附到该边缘。吸附只影响位置，不改变尺寸。

### 14.10 补充 I：透明度

参考 PRD 建议 100%、90%、80%、70% 四档透明度。当前方案没有透明度设置。

透明度会影响整个无边框窗口，包括硬件视频表面和悬浮控制层；不同 Windows/X11 合成器的表现可能不同，且透明视频可能降低可读性和硬件合成稳定性。

**最终裁定 I1：** v0.2.27 不加入透明度设置，保留为后续增强项。

### 14.11 补充 J：小窗锁定

参考 PRD 建议增加锁定开关，开启后禁止拖动和缩放。该功能与本文件的边缘缩放、标题栏拖动并不冲突，技术实现较小，但需要在迷你控制条增加锁定状态和解锁入口。

**最终裁定 J1：** 纳入本版本，默认不锁定；锁定后仍允许按钮、进度条、音量滑块和键盘操作，只禁用窗口移动/缩放。

### 14.12 补充 K：托盘、贴边隐藏、鼠标穿透和系统 PIP

参考 PRD 11.2-11.5 提出的托盘恢复、贴边自动隐藏、鼠标穿透和系统 Picture-in-Picture 属于独立扩展：

- 托盘需要新增应用生命周期和后台播放策略；
- 贴边隐藏会与拖动、置顶和多屏边界产生额外交互；
- 鼠标穿透会使标题栏和控制条无法操作，必须增加独立的切换入口；
- 系统 PIP 依赖操作系统能力，不能保证 Windows 与 Fedora X11 一致。

**最终裁定 K1：** 四项均列为后续版本，不纳入 v0.2.27 首次小窗实现。

### 14.13 性能指标处理

参考 PRD 给出进入/恢复不超过 500ms、CPU 增量不超过 5%、内存增量不超过 100MB、连续切换 100 次无崩溃等指标。

**最终裁定 L1：**

- 进入/恢复 500ms 作为 Windows 常规窗口的目标值，以 p95 测量，不把网络或 mpv 首次初始化时间计入；
- 连续切换 100 次纳入自动化/人工稳定性测试；
- CPU/内存作为观察指标，记录空闲播放基线与小窗状态差值，不将不同硬件和视频编码的绝对 5%/100MB 作为跨机器硬失败条件；
- 发生黑屏、花屏、卡死或播放重载则直接判定失败。

### 14.14 最终合并基线

参考 PRD 对照项 A-L 的正式编码基线为（与第 13 节原始需求 A-H 编号相互独立）：

```text
A：全屏按钮后面
B：B1，复用主窗口，不支持主窗口关闭后独立播放
C：采用自绘标题栏和迷你控制条
D：D1，方向键保持 10 秒
E：增加 1 秒播放/暂停反馈
F：F1，结束层提供重新播放、返回播放器
G：G1，持久化几何和静音并安全校验
H：H1，右下角默认位置 + 20px 边缘吸附
I：I1，本版本不做透明度
J：J1，加入小窗锁定
K：K1，托盘/贴边隐藏/鼠标穿透/系统 PIP 后续处理
L：L1，按 p95 和稳定性指标验收
```

原始需求 A-H 与参考 PRD 对照项 A-L 均已采用推荐裁定并回写正文，不再保留待裁定项。本文件作为 v0.2.27 编码实施基线。
